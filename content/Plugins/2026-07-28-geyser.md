# Geyser

Geyser allows Minecraft: Bedrock Edition players to connect to a Minecraft: Java Edition server.

Geyser translates Bedrock network traffic into traffic the Java server understands.

# Supported Devices

Bedrock players may connect from devices such as:

- Windows Bedrock Edition

- Android

- iPhone and iPad

- Xbox

- PlayStation

- Nintendo Switch

Console connections may require additional setup because consoles do not normally allow arbitrary external servers to be added directly.

# Joining LowFrame

Bedrock address:

`54.39.152.135`

Bedrock port:

`8045`

Java players should continue using the normal Java address.

# Player Guide

Bedrock players connect through Geyser automatically.

Players do not need to install a Java mod or own Java Edition when Floodgate is also configured.

## Differences From Java Edition

Some features may look or behave differently because the Bedrock and Java editions are not identical.

Possible differences include:

- Menus

- Off-hand use

- Combat controls

- Item placement

- Custom resource-pack items

- Command suggestions

- Chat formatting

- Redstone behavior shown by the client

- Some particles and sounds

The Java server remains responsible for gameplay.

# Server Setup

## Paper or Spigot Installation

1. Stop the server.

2. Download Geyser-Spigot.

3. Upload the plugin to:

`plugins`

4. Start the server.

5. Open:

`plugins/Geyser-Spigot/config.yml`

6. Configure the Bedrock address and port.

7. Restart the server.

8. Allow the selected port through UDP.

## Velocity Installation

For a Velocity network, install Geyser on the proxy.

1. Stop Velocity.

2. Download Geyser-Velocity.

3. Upload it to Velocity's:

`plugins`

4. Start Velocity.

5. Open the generated Geyser configuration.

6. Set the Bedrock listening port.

7. Restart Velocity.

8. Test every backend server.

Geyser should normally be installed only on the proxy when using Velocity.

## Bedrock Port

Example:

    bedrock:

      address: 0.0.0.0

      port: 8045

The Bedrock port uses UDP.

Opening only TCP is not enough.

Do not use the same UDP port for another service such as voice chat or query.

## Authentication

Geyser supports different authentication types.

To allow Bedrock players to join without owning Java Edition, use Floodgate and set:

`auth-type: floodgate`

## ViaVersion

Geyser imitates a supported modern Java client when connecting to the backend.

When the backend server is older, ViaVersion may be required.

On a Velocity network, run:

`/viaversion probe`

to confirm backend versions are detected properly.

# Commands

Commands may be entered as:

`/geyser <subcommand>`

or in the console without the slash.

## Help

`/geyser help`

## Version

`/geyser version`

Displays version and supported protocol information.

## Reload

`/geyser reload`

A full restart is recommended after major configuration changes.

## Connection Test

`/geyser connectiontest <address> <port>`

Example:

`/geyser connectiontest 54.39.152.135 8045`

This checks whether the Bedrock UDP port can be reached.

## List Players

`/geyser list`

Displays players connected through Geyser.

## Dump

`/geyser dump`

Creates diagnostic information for troubleshooting.

Review the dump before sharing it publicly.

# Recommended Velocity Setup

A typical network layout is:

- Velocity

  - Geyser

  - Floodgate

  - ViaVersion when required

- Lobby

  - Normal Paper plugins

- SMP servers

  - Normal Paper plugins

Floodgate may additionally be installed on backend servers when its API or improved skin forwarding is required.

# Troubleshooting

## Unable to Connect to World

Check:

- The Geyser port is open for UDP

- The correct public address is being used

- The port is not already in use

- Geyser loaded successfully

- The proxy is online

- The firewall allows the port

- The hosting provider supports additional UDP ports

Run:

`/geyser connectiontest <address> <port>`

## Java Works but Bedrock Does Not

This normally indicates a Geyser, UDP-port, firewall, or Floodgate issue rather than a normal Java server issue.

Check the Geyser console output first.

## Players Reach the Wrong Backend

Check:

- Velocity's `try` server list

- Forced-host settings

- Floodgate forwarding

- Geyser's remote server configuration

- Whether a direct backend address was entered accidentally

## Bedrock Players Need a Java Account

Install Floodgate and change Geyser's authentication type to:

`floodgate`

## Outdated Server

Update Geyser and ViaVersion.

Also confirm that the backend server accepts the Java protocol version Geyser is currently imitating.

## Resource Pack Problems

Bedrock cannot directly use normal Java resource packs.

Custom Java items may require additional Bedrock resource-pack configuration.

## Updating Geyser

1. Stop the proxy or server.

2. Back up the Geyser folder.

3. Replace the Geyser plugin.

4. Update Floodgate when required.

5. Update ViaVersion when required.

6. Start the network.

7. Test Bedrock login.

8. Test transfers to every backend.
